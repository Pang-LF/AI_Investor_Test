This replay used Robinhood's official Agentic Trading MCP to retrieve 5-minute
regular-hours bars for all 60 symbols. The cutoff was 13:00 ET: the last usable

bars through September 9. No order-review or order-placement tool was called.

## Important validity boundary

This is an integration replay, not an unbiased backtest. The only locally saved
September 10 universe was created after the close by the older universe builder.
Its event bucket therefore knew which stocks became large full-day movers. That
selection creates look-ahead bias, even though the price bars and forecast cutoff
are point-in-time correct. Historical bid/ask and a 13:00 account snapshot were
also unavailable. Portfolio state is assumed to be $1,000 cash with no positions.

The result can validate data retrieval, forecast gating, no-trade behavior, and
logging. It cannot be used to claim expected performance or validate universe
selection quality.

## Is the 55% probability gate too strict?

The 0.50% expected-return threshold was not restrictive in this replay: 29 of 46
forecasts passed it. The probability gate rejected them. Across the 46 forecasts,
the median probability was 46.8% and the maximum was 50.0%. The 20-day validation
errors had a -1.53% median and only 43.2% were positive, so the empirical
calibrator was correctly expressing weak recent validation reliability rather
than merely clipping otherwise strong forecasts.

A walk-forward sensitivity check over the latest 30 available completed-daily
cutoffs produced the following frequency of at least one candidate. It uses the
same static hindsight-contaminated universe, so it diagnoses gate activity but
does not estimate investable performance:

| Probability threshold | Cutoffs with at least one candidate | Frequency |
|---|---:|---:|
| 55% | 2 / 30 | 6.7% |
| 52% | 3 / 30 | 10.0% |
| 50% | 13 / 30 | 43.3% |
| 48% | 24 / 30 | 80.0% |

Thus 55% is attainable but deliberately sparse, and in the recent regime it can
leave the system inactive for weeks. Lowering to 52% would barely change that.
Lowering to 48% would frequently admit forecasts that the model itself estimates
as less likely than not to outperform SPY, which is not a defensible execution
rule.

A better challenger is to separate the research and execution gates instead of
using one cutoff for both. A 48% research threshold could send a small bounded
set to qualitative review, while execution would still require at least 50%, a
larger expected-return-to-uncertainty ratio, and an LLM `allow`. That design must
be evaluated prospectively before replacing the current LIVE policy; no threshold
was changed as part of this replay.

## Strategy v0.5.0 gate recalculation

After the original replay, three years of completed daily bars were retrieved for
the same static 60-name universe and passed through the v0.5.0 research and
calibration gates. No LLM or broker order tool was called. The research gate
selected DELL, NBIS, BE, SNDK, and BHVN. The longer sample changed the median
20-day OOS residual from the short-window diagnosis to +0.73%, demonstrating the
instability of treating a single recent overlapping window as a production
calibration.

The 20-day diagnostic retained seven non-overlapping date blocks containing 404
cross-sectional observations. Realized mean excess return / win rate by selected
edge-ratio bucket was: 0–0.05: +0.24% / 54.5%; 0.05–0.10: +0.60% / 52.2%;
0.10–0.15: +2.17% / 52.6%; 0.15–0.25: +10.98% / 71.8%; and >=0.25: -1.24% /
50.0%. The apparently strong 0.15–0.25 result spans only seven date blocks, while
the >=0.25 result spans only two, so neither supports a robust production
threshold. The static hindsight-contaminated universe adds another selection
bias.

Strategy v0.5.0 therefore retains `execution_calibration_approved = false`.
These five names remain research-only and the execution candidate set is empty.
This recalculation is a gate-behavior diagnostic, not a backtest and not evidence
that any name should have been purchased.
